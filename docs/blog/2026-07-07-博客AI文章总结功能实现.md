# 博客新增 AI 文章总结功能：从后端生成到前台打字机展示

最近给博客系统增加了一个 AI 文章总结功能。它可以在后台为文章生成一段摘要，管理员审核通过后，前台文章详情页会以打字机效果展示这段总结，让读者在阅读正文前快速了解文章内容。

## 实现了什么功能

这次主要完成了四部分能力：

1. 后端支持 AI 文章总结生成。
2. AI 接口配置改为从数据库读取。
3. 后台支持生成、编辑和审核 AI 总结。
4. 前台文章详情页展示已审核总结，并增加打字机效果。

整体流程如下：

```text
后台配置 AI 参数
      ↓
后台点击生成 AI 总结
      ↓
后端请求 AI 接口并保存总结
      ↓
管理员审核总结
      ↓
前台文章详情页展示总结
```

## 数据库字段设计

为了保存 AI 总结内容，在 `tb_article` 表中增加了三个字段：

```sql
ai_summary        text      null comment 'AI文章总结',
ai_summary_status tinyint   null comment 'AI总结状态 0未生成 1已生成 2已审核',
ai_summary_time   datetime  null comment 'AI总结生成时间'
```

其中 `ai_summary_status` 用来控制展示状态：

| 状态 | 含义 |
| --- | --- |
| 0 | 未生成 |
| 1 | 已生成，等待审核 |
| 2 | 已审核，允许前台展示 |

这样做的好处是，AI 生成的内容不会直接展示到前台，而是需要后台审核后才公开，避免 AI 内容不准确或不合适时直接影响用户体验。

## AI 配置放到网站配置表

AI 的接口地址、密钥、模型等信息没有写死在代码或配置文件里，而是放到了 `tb_website_config` 的配置 JSON 中。

后台网站配置页新增了 AI 配置项，例如：

- 是否开启 AI 总结
- AI 接口地址
- 接口类型
- API Key
- 模型名称
- 推理强度
- 是否关闭响应存储
- 自定义总结提示词

这样后续更换模型、切换服务地址、调整 prompt 时，不需要重新改代码和部署项目。

## 后端如何生成总结

后端新增了生成文章总结接口：

```http
POST /admin/articles/{articleId}/ai-summary
```

接口处理流程大致如下：

1. 根据文章 ID 查询文章内容。
2. 读取网站配置中的 AI 参数。
3. 校验 AI 总结功能是否开启。
4. 根据接口类型构造请求体。
5. 请求 AI 服务生成总结。
6. 解析 AI 返回结果。
7. 保存总结内容、状态和生成时间。

生成成功后，文章状态会被设置为：

```text
ai_summary_status = 1
```

也就是“已生成，待审核”。这一步不会直接让前台展示总结。

## 兼容 Responses API

这次后端不只支持传统的 Chat Completions 格式，也兼容了 Responses API。

如果配置的接口类型是 `responses`，后端会构造类似这样的请求：

```json
{
  "model": "gpt-5.5",
  "instructions": "你是博客文章总结助手...",
  "input": "文章标题和正文内容...",
  "reasoning": {
    "effort": "high"
  },
  "store": false
}
```

返回结果解析时，也兼容了不同格式：

- `output_text`
- `output[].content[].text`

这样可以适配不同 AI 服务商的 OpenAI 兼容接口。

## 后台文章页增加审核入口

在后台文章编辑页中，增加了 AI 总结相关操作：

- 生成 AI 总结
- 查看生成后的总结内容
- 手动修改总结
- 设置总结状态
- 标记为已审核

后台生成成功后，管理员可以看到 AI 返回的总结内容。确认无误后，将状态改为“已审核”，前台才会展示。

这样的设计让 AI 只负责辅助生成，最终内容仍由管理员把关。

## 前台如何展示 AI 总结

前台文章详情页只展示满足条件的 AI 总结：

```ts
article.aiSummary && article.aiSummaryStatus === 2
```

也就是说：

- 没有总结，不展示。
- 已生成但未审核，不展示。
- 已审核，展示。

展示位置放在文章正文上方，让读者进入文章后第一时间看到摘要。

## 打字机效果实现

为了让展示效果更自然，前台没有一次性渲染完整总结，而是做了打字机效果。

核心思路是：

1. 进入文章详情页后获取文章数据。
2. 判断是否存在已审核 AI 总结。
3. 使用 `Array.from()` 将总结拆成字符数组。
4. 使用 `setInterval` 逐字追加到展示文本中。
5. 页面卸载或重新拉取文章时清理定时器。

简化后的逻辑如下：

```ts
const typedAiSummary = ref('')
const aiSummaryTyping = ref(false)
const aiSummaryTypingTimer = ref<number | null>(null)

function startAiSummaryTyping() {
  clearAiSummaryTypingTimer()
  typedAiSummary.value = ''

  if (!article.value.aiSummary || article.value.aiSummaryStatus !== 2) {
    return
  }

  const summaryChars = Array.from(article.value.aiSummary)
  let currentIndex = 0
  aiSummaryTyping.value = true

  aiSummaryTypingTimer.value = window.setInterval(() => {
    typedAiSummary.value += summaryChars[currentIndex]
    currentIndex += 1

    if (currentIndex >= summaryChars.length) {
      clearAiSummaryTypingTimer()
      aiSummaryTyping.value = false
    }
  }, 45)
}
```

使用 `Array.from()` 是为了更好地处理中文字符和部分特殊字符，避免普通字符串截取导致显示异常。

## 样式优化

AI 总结卡片的样式也做了调整：

- 宽度与文章正文保持一致。
- 背景改为白色。
- 使用轻量边框和阴影。
- 保留蓝色光标动画。
- 移动端自适应正文宽度。

这样 AI 总结不会显得突兀，整体上更像文章内容的一部分。

## 最终效果

现在的文章总结流程更加完整：

```text
AI 自动生成
管理员审核
前台优雅展示
```

这个功能既提升了文章阅读体验，也保留了内容审核的主动权。后续还可以继续扩展，比如：

- 支持批量生成历史文章总结。
- 增加重新生成按钮。
- 总结失败时记录错误原因。
- 增加总结风格配置。
- 在文章列表页展示短摘要。

整体来看，这次功能不仅是简单地接入 AI 接口，而是围绕博客系统已有的后台、配置、数据库和前台展示流程，做了一套相对完整的 AI 总结能力。
