# Blog App 雾白柔和黑白 UI 美化设计

## 背景

`blog-front/blog-app` 是 uni-app + Vue 3 移动端博客应用，页面集中在 `pages/*`，全局样式和设计令牌主要在 `uni.scss` 与 `App.vue`。当前项目已有浅色/深色主题变量、卡片化布局、通知、登录、文章详情、个人中心等页面。

用户希望对 App UI 做美化，并明确偏好“颜色没那么深的黑白配”。最终选择方案为“全局视觉系统 + 核心页面统一美化”，视觉方向为“雾白柔和”。

## 目标

- 将默认浅色主题调整为柔和黑白灰体系，减少绿色主色存在感。
- 统一核心页面的背景、卡片、按钮、标签、列表、空状态、加载状态和文字层级。
- 保持博客阅读体验优先，避免大面积纯黑造成压迫感。
- 保留现有业务逻辑、路由、接口和状态管理，不做功能重构。
- 保留暗色主题能力，但本次重点打磨默认浅色视觉。

## 非目标

- 不重做后端接口或数据结构。
- 不引入新的 UI 框架。
- 不重构全部页面交互流程。
- 不修改 `unpackage` 产物目录。
- 不制作营销落地页或纯展示页。

## 视觉方向

采用“雾白柔和黑白”风格：

- 页面背景：雾白、暖白、浅灰，例如 `#f6f6f3`、`#fbfbfa`。
- 卡片背景：白色或近白，例如 `#ffffff`、`#fbfbfa`。
- 主文字：炭黑，例如 `#252525`。
- 强调操作：小面积深灰黑，例如 `#3a3a3a`。
- 辅助文字：中性灰，例如 `#777777`、`#9a9a96`。
- 边框：浅灰，例如 `#e8e8e3`、`#deded8`。
- 阴影：低透明黑色阴影，控制在轻微层次，不做重投影。
- 绿色：从主导航、主按钮和主要选中态中移除；成功状态如必须保留，可改为低饱和中性色提示。

## 页面范围

第一阶段覆盖核心体验页面：

## 全局样式设计

在 `uni.scss` 和 `App.vue` 中统一调整设计令牌：

- `$primary` 从绿色改为炭灰黑，并同步 primary 灰阶。
- 背景、卡片、文字、边框、阴影变量改为雾白黑白体系。
- `page` CSS 变量与 SCSS 令牌保持语义一致。
- 保持 `rpx` 尺寸体系和现有动画工具类。
- 统一按钮、卡片、标签、输入框、列表行的视觉基准。

## 组件和页面规则

- 卡片使用白色背景、浅灰边框和轻阴影，圆角保持现有移动端友好风格。
- 主按钮使用炭灰背景和白字，次按钮使用白底、浅灰边框和炭灰字。
- 标签使用浅灰底与中灰字，不使用高饱和色块。
- 列表行保持足够点击区域，使用细分割线或浅灰卡片间距区分。
- 空状态和加载状态使用中性灰，不出现强彩色插画。
- 图标保持单色中性风格，跟随文字层级。
- 暗色主题继续使用现有 `theme-dark` 机制，避免被浅色变量破坏。

## 数据流和行为

本次 UI 美化不改变数据流：

- Pinia store 使用方式不变。
- API 调用不变。
- 页面生命周期不变。
- 登录、通知 WebSocket、系统通知点击、文章操作等行为不变。

任何模板调整必须保持现有事件绑定和导航路径不变。

## 错误处理

错误提示、空数据、网络失败、未登录提示统一使用中性视觉：

- Toast 文案和调用方式不变。
- 空状态颜色改为浅灰黑白体系。
- 未读、失败、成功等状态不新增复杂规则；必要状态色用低饱和表达，避免破坏黑白主调。

## 验证

实现完成后需要执行：

- 检查 `git diff`，确认没有修改 `unpackage` 产物。
- 运行项目可用的构建或预览命令；如果 `package.json` 没有脚本，则说明限制，并用 HBuilderX/uni-app 项目结构做静态检查。
- 检查核心页面模板中主要类名仍存在，事件绑定未丢失。
- 如果能启动 H5 预览，则用浏览器检查首页、文章详情、分类、通知、我的、登录页的布局和文本不重叠。

## 风险

- 项目文本存在编码显示异常，修改时必须避免无关文案 churn。
- 页面样式可能大量写在单文件组件内，需要逐页保持作用域清晰。
- 深色主题与浅色默认主题共享变量，改动时要避免暗色模式对比度下降。
- uni-app 多端样式兼容需要避免使用不稳定 Web-only CSS。
