# 菜单加载修复说明

## 问题分析

通过对比 Vue2 和 Vue3 版本，发现了以下关键问题：

### 1. Token 格式问题 ✅ 已修复
- **Vue2**: `Authorization: Bearer <token>`
- **Vue3**: 已正确实现 Bearer 前缀（request.js 第32行）

### 2. 菜单接口路径问题 ✅ 已修复
- **正确路径**: `/admin/user/menus`
- **返回格式**: `{flag: true, code: 20000, message: "操作成功", data: [...]}`
- **响应拦截器**: 已修复为返回 `res.data.data || res.data`

### 3. 组件路径映射问题 ✅ 已修复
- **数据库路径格式**: `/home/Home.vue`, `/article/ArticleList.vue`
- **Vue2 文件结构**: `views/home/Home.vue`, `views/article/ArticleList.vue`
- **Vue3 文件结构**: `views/blog/home/index.vue`, `views/blog/article/list.vue`
- **解决方案**: 在 `loadView()` 函数中添加完整的路径映射表

### 4. 路由动态加载流程 ✅ 已修复
- **Vue2 流程**:
  1. 登录成功 → 存储 token 和用户信息到 localStorage
  2. 路由守卫检测未加载菜单 → 调用 `generaMenu()`
  3. `generaMenu()` 请求 `/admin/user/menus` → 处理菜单数据
  4. 动态添加路由 → `next({ ...to, replace: true })` 重新导航
  
- **Vue3 流程**:
  1. 登录成功 → Pinia 存储用户信息 + localStorage 存储 token
  2. 路由守卫 (permission.js) → 调用 `getInfo()` 获取用户信息
  3. 调用 `generateRoutes()` 加载菜单 → 动态添加路由
  4. `return { ...to, replace: true }` 重新导航

### store/modules/permission.js

```javascript
// 1. 组件路径处理（第122-128行）
route.component = route.component.trim()
if (route.component.startsWith('/')) {
  route.component = route.component.substring(1)
}
if (route.component.endsWith('.vue')) {
  route.component = route.component.replace(/\.vue$/, '')
}

// 2. 路径映射表（第170-206行）
const pathMap = {
  'home/Home': 'blog/home/index',
  'article/Article': 'blog/article/edit',
  'article/ArticleList': 'blog/article/list',
  // ... 更多映射

// 3. loadView 函数使用映射

```

### permission.js (路由守卫)

```javascript
// 已正确实现动态路由加载和重新导航
const accessRoutes = await usePermissionStore().generateRoutes()
accessRoutes.forEach(route => {
  if (!isHttp(route.path)) {
    router.addRoute(route)
  }
```
