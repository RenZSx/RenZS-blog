## 二、手动清理路由和引用（5分钟）

### 步骤 1: 清理路由配置

编辑 `src/router/index.js`，定位到第 **101-172** 行：

**删除前：**
```javascript
// 动态路由，基于用户权限动态去加载
export const dynamicRoutes = [
  {
    path: '/system/user-auth',
    component: Layout,
    // ... 大量若依路由配置
  },
  // ... 其他路由
]
```

**修改为：**
```javascript
// 动态路由，基于用户权限动态去加载
export const dynamicRoutes = []
```

### 步骤 2: 清理 main.js 引用

编辑 `src/main.js`，查找并删除以下内容（如果存在）：

**删除这些导入：**
```javascript
import { getDicts } from "@/api/system/dict/data"
import { getConfigKey } from "@/api/system/config"
```

**删除这些全局属性：**
```javascript
app.config.globalProperties.getDicts = getDicts
app.config.globalProperties.getConfigKey = getConfigKey
```

### 步骤 3: 检查字典工具（可选）

如果 `src/utils/dict.js` 未被博客功能使用，可删除：
```bash
# 先搜索是否有引用
grep -r "import.*dict" src/ --exclude-dir=node_modules

# 如果只有若依模块引用，则删除
rm -f src/utils/dict.js
```

## 六、常见问题

### Q1: 脚本执行后提示"命令不存在"？
**A:** Windows 用户双击 `cleanup.bat`，Linux/Mac 用户确保已执行 `chmod +x cleanup.sh`

### Q2: 编译报错找不到 @/api/system/xxx？
**A:** 说明还有文件引用了已删除的API，全局搜索该引用并删除：
```bash
grep -r "@/api/system/dict" src/
```

### Q3: 页面空白或报错？
**A:** 检查 F12 控制台，查看具体错误信息，通常是路由配置问题

### Q4: 删除后能正常运行，但某个功能报错？
**A:** 检查该功能是否依赖了已删除的模块：
- 字典管理 → 可能有下拉选项使用了字典
- 参数配置 → 可能有配置项使用了系统参数

### Q5: 想保留某些若依功能怎么办？
**A:** 在执行清理脚本前，先将脚本中对应的删除命令注释掉

### Q6: 删除后打包体积没明显变化？
**A:** 
1. 清理 node_modules 后重新 `npm install`
2. 执行 `npm run build:prod --report` 查看体积分析
3. 检查是否有其他大文件（如图片、字体）
